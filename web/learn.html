Keep the evaluation within the beta scope

MayoAuth is an early beta identity foundation. Use non-sensitive test identities and a separate test application while evaluating the documented behavior. The public sample workspace is a browser simulation; it does not create real identities or issue tokens. Do not mistake a convincing demo screen for evidence that a real authentication integration has been configured.

Name the intended flow and exact destination

Record which application begins the sign-in, the intended issuer, and the exact callback you will configure in your private setup. Use placeholder domains in this public worksheet and keep client secrets and deployment inventories elsewhere. MayoAuth’s documented OIDC integration uses authorization code with PKCE S256 and exact callback registration. Follow the project’s current docs for real configuration rather than deriving settings from this planning exercise.

Test the failure path as well as the happy path

Choose an expected successful return and a deliberately unregistered callback that must be rejected in the test environment. Record logout expectations and what remains unimplemented in the beta. Built-in MFA, SAML, SCIM, refresh tokens, self-service recovery, and multi-tenant Cloud are not currently implemented. This worksheet provisions no identity, registers no client, and does not establish production readiness or an independent security review.
