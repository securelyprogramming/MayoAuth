# Open source and Premium

The commercial boundary is operational responsibility. Core identity should not
be a reason to buy a higher tier.

| Capability | Community | Cloud Free (planned) | Premium (planned) |
| --- | --- | --- | --- |
| Software license | Apache-2.0 | Same engine | Same engine |
| Users | Uncapped; infrastructure-bound | Up to 20 | Managed capacity beyond 20 |
| OIDC, core connectors, CLI | Included | Included | Included |
| Audit export and basic metrics | Included | Included | Included |
| Built-in MFA | Planned in Community | Same engine | Same engine |
| Hosting and updates | Operator-managed | Service-managed | Service-managed |
| Retention and backups | Operator chooses and manages | Bounded default | Longer managed retention and restore assistance |
| Operations and support | Community issues | Basic managed service | Priority response, operational alerts, service commitments |

Cloud, Premium, billing, support response times and availability commitments are
not implemented. Pricing is undecided. No payment is collected in this beta.
The browser demo's 20-user boundary is for synthetic sample data, not a hosted
production entitlement. There is no license enforcement in the Community engine.

Keep actual customers, credentials, contracts, billing and private operational
inventory in the separate commercial operations repository. Keep reusable engine
improvements public. Do not copy another project's private operational code.
